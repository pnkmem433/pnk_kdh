# Phase 2(옷1벌) 분석지침

## 목적
- Phase 2 CSV 결과를 실제 사용자 환경 기준으로 일관되게 해석한다.
- Phase 1 분석 원칙은 참고하되, Phase 2에서는 `의류별 RFID 태그` 또는 `단일 측정 태그`를 기본 분석 단위로 사용한다.
- 이 문서는 `옷 1벌 기준 Phase 2` 분석과 이후 후반 다중 의류/스트레스 테스트 비교의 기준선으로 사용한다.

## 문서 사용 원칙
- Phase 2 `옷 1벌` 분석을 할 때는 이 문서를 최우선 기준으로 사용한다.
- Phase 1 참조 문서는 `phase1분석결과.md`, `p1db.json`이다.
- 이후 사용자가 `phase2 기준으로 분석`, `phase2 옷1벌 기준으로 분석`이라고 요청하면 이 문서를 기준으로 해석한다.

## 기본 통계 처리 원칙
- 각 테스트 조건은 5회 반복 측정한다.
- 각 조건별 측정값에서 최고치 1개와 최저치 1개를 제외하고, 나머지 3회의 평균값을 최종 통계값으로 사용한다.
- 적용 대상:
  - 최초 인식 시간
  - 태그별 누적 인식 횟수
  - 조건별 총 인식 수
  - 서버 전송까지 걸린 시간
- 최초 인식 시간이 없으면 `-`로 표기한다.
- 숫자는 원값 그대로 사용하며 임의로 보정하지 않는다.

- 다중 태그 중첩 테스트

## 의류/태그 명명 규칙
- 분석 전에 RFID 값과 의류 특징을 1:1로 고정 매핑한다.
- 최종 분석 결과에는 EPC 원문보다 사람이 바로 구분할 수 있는 이름을 우선 사용한다.
- 현재 확정 매핑:
  - `파란셔츠 = U3400AA00001000000217C816B9B50634`
- 이후 사용자가 의류 특징과 EPC를 알려주면 그 매핑 기준으로 계속 동일하게 분석한다.
- 파일명 또는 제목에 `파란셔츠`가 포함되어 있으면 우선적으로 `U3400AA00001000000217C816B9B50634` 태그의 인식 결과를 추적한다.

## CSV 파일명 해석 규칙
- CSV 파일명에는 가능한 한 아래 정보를 포함한다.
  - 테스트 구분: `single_cover`, `multi_tag`
  - 바닥 위치: `center`, `left`, `right`, `front`, `back`
  - 중첩 수: `1layer`, `2layer`, `3layer`
  - 의류 순서: `red-top_blue-mid_yellow-bottom`
  - 태그 방향: `front`, `flip`, `vertical`
  - 반복 번호: `run1` ~ `run5`
- 예시:
  - `single_cover_center_3layer_tag-red_bottom_cover-blue-yellow_run1.csv`
  - `multi_tag_left_red-top_blue-mid_yellow-bottom_run3.csv`
  - `multi_tag_center_yellow-top_red-mid_blue-bottom_run5.csv`
- 위치 정보가 파일명에 포함되어 있으면 분석 시 반드시 반영한다.

- 반복 누락 여부
- 바닥 위치별 편차
- 순서 변경에 따른 편차

## 의류 자체 간섭 테스트 분석 항목
- 태그 없는 의류가 1겹 추가될 때 인식 횟수 감소 여부
- 태그 없는 의류가 2겹 추가될 때 인식 횟수 감소 여부
- 태그가 맨 아래에 위치할 때 최초 인식 시간 지연 여부
- 같은 중첩 조건에서 위치만 바뀌었을 때 성능 차이 여부

## 다중 태그 중첩 테스트 분석 항목
- 상단/중단/하단 의류별 평균 인식 횟수
- 같은 의류가 상단일 때와 하단일 때 인식 차이
- 순서 6가지 경우의 수에서 특정 의류가 반복적으로 불리한지 여부
- 바닥 위치별로 특정 의류 태그만 반복 누락되는지 여부

## 위치 분석 원칙
- 바닥 위치는 CSV 파일명 기준으로 구분한다.
- 기본 위치 구분:
  - `center`
  - `left`
  - `right`
  - 필요 시 `front`
  - 필요 시 `back`
- 같은 순서라도 위치가 바뀌면 별도 조건으로 본다.
- 같은 하단 의류가 위치에 따라 읽힘 횟수가 다르면 바닥 위치 영향을 우선 의심한다.

## 훅 조건 해석 주의사항

| 조건 | 반영 규칙 |
| --- | --- |
| 훅에 걸린 의류 | 바닥과 표면 재질이 다르므로 동일 위치라도 결과를 그대로 동등 비교하지 않고 구조 차이를 고려 |
| 훅 주변 표면이 거칠고 재질이 다름 | 난반사 또는 산란성 반사 가능성을 해석 메모에 반영 |
| 후면 배치 | 훅 구조물, 벽면, 의류 차폐가 함께 겹칠 수 있으므로 위치 영향보다 더 큰 손실 가능성을 별도 메모 |
| 수치 처리 | 실제 CSV 값은 절대 임의 보정하지 않고 원값 그대로 사용 |

## 훅/후면 해석 문장 규칙

| 상황 | 권장 해석 |
| --- | --- |
| 훅 + 후면 + 급감 | 의류 차폐, 태그 방향 불리함, 훅 표면/벽면 산란 영향이 중첩된 조건으로 해석 |
| 훅 + 정면 + 유지 | 의류가 있어도 해당 위치/방향에서는 실사용 영향이 크지 않은 조건으로 해석 |
| 훅 + 후면 + 0회 | 단순 편차가 아니라 실제 운영 누락 위험 조건으로 해석 |

## 정면/후면 차폐 해석 규칙

| 조건 | 해석 규칙 |
| --- | --- |
| 훅에서 정면을 보고 있고 태그가 옷 안에 있음 | 이 조건에서 인식 저하가 거의 없으면 해당 위치에서는 `옷 1겹`에 따른 영향이 거의 없다고 해석 |
| 훅에서 정면을 보고 있고 태그가 옷 밖에 있음 | 기준선 대비 성능이 유지되면 태그와 훅 구조의 기본 결합은 양호하다고 해석 |
| 훅에서 후면으로 돌린 상태 | 옷이 한 번 더 겹치는 효과가 있어 `옷 2겹` 영향 가능성은 있으나, 우선적으로는 훅 표면, 벽면, 방향 불일치에 따른 반사/산란 문제를 먼저 의심 |
| 후면 조건에서만 급격히 저하 | 단순히 옷 두께 때문이라고 단정하지 말고, `반사 문제 > 차폐 문제` 순서로 우선 해석 |
| 정면 조건은 유지되고 후면 조건만 무너짐 | 해당 위치는 의류 1겹 차폐보다 후면 반사 구조 영향이 더 큰 조건으로 해석 |
| 정면과 후면 모두 저하 | 의류 차폐와 위치 자체의 음영 문제가 함께 있는 조건으로 해석 |

## 결과 해석 기준

### 1. 의류 자체 간섭 영향
- 태그 없는 옷이 추가될수록 측정 태그 인식 횟수가 뚜렷하게 감소하면 의류 차폐 영향으로 본다.
- 최초 인식 시간이 반복적으로 증가하면 의류 차폐 또는 적치 구조 영향으로 본다.
- 동일 위치에서 10초 내 미인식 사례가 늘어나면 차폐 영향이 강한 조건으로 본다.

### 2. 중첩 순서 영향
- 같은 의류라도 상단일 때보다 하단일 때 인식 횟수가 지속적으로 낮으면 중첩 순서 영향으로 본다.
- 순서가 바뀌면 특정 의류의 인식 성능이 함께 바뀌는지 확인한다.

### 3. 바닥 위치 영향
- 동일 중첩 구조인데 위치에 따라 인식 횟수 차이가 반복 발생하면 위치 영향으로 본다.
- 특정 위치에서 특정 의류만 자주 누락되면 위치 + 적치 구조 영향으로 본다.
- 특정 위치에서 전체 인식 수가 낮으면 바닥 음영지역 가능성을 함께 본다.

### 4. 다중 태그 간섭 영향
- 단일 태그 조건 대비 다중 태그 조건에서 전체 평균 인식 횟수가 감소하면 다중 태그 간섭 가능성을 본다.
- 의류 차폐만으로 설명하기 어려운 동시 누락이 늘어나면 태그 간 간섭 가능성을 본다.
- 서버 전송 성공률이 다중 태그 조건에서만 감소하면 최소 인식 횟수 기준과 함께 검토한다.

## 후반 인식 누락 시 해석 규칙

| 후반 현상 | 초반 비교 결과 | 우선 해석 |
| --- | --- | --- |
| 초반에도 원래 안 읽힘 | 동일 위치 단일 의류부터 취약 | 원래 사각지대 성격 |
| 초반엔 읽혔는데 후반만 누락 | 단일 의류 기준선은 양호 | 밀집도/재질/태그 간섭 추가 영향 |
| 훅은 무너지고 바닥은 유지 | 초반에도 훅 취약, 바닥 강함 | 반사/방향/구조 영향이 큼 |
| 바닥도 후반에 무너짐 | 초반 바닥은 안정적 | 자체 차폐, 태그 매몰, 비정형 뭉침 가능성 큼 |
| 특정 의류만 반복 누락 | 같은 위치 다른 의류는 읽힘 | 재질, 태그 부착 방향, 태그 위치 문제 가능성 |

## 후반 원인 역추적 연결 규칙

### 1. 밀집도 배제
- 초반에 단일 의류로는 잘 읽혔던 위치인데, 후반 다중 의류에서만 누락되면 `태그 간 상호 간섭` 가능성을 우선 본다.
- 의류를 10cm 이격 후 인식이 회복되면 `밀집도 원인`으로 판정한다.

### 2. 재질 배제
- 초반 바닥/훅 단일 의류에서는 읽혔는데, 후반에서 특정 두꺼운 겉옷 뒤에 숨은 의류만 누락되면 `원단 차폐` 가능성을 본다.
- 겉옷 제거 후 회복되면 `재질 차폐 원인`으로 판정한다.

### 3. 위치 배제
- 후반 특정 훅/구석에서만 누락되고 중앙으로 옮기면 회복되면 `물리적 사각지대`로 본다.
- 초반 위치 결과와 비교해 원래 취약 위치인지도 함께 기록한다.


## 특이사항 기록 규칙
- 특정 의류만 반복 누락
- 하단 의류 인식 실패
- 특정 위치에서만 성능 저하
- 방향 뒤집힘 시 성능 급감
- 10초 내 인식 실패 후 재시도에서만 성공
- 서버 전송은 되었지만 누적 인식 횟수가 낮았던 경우

## 분석 작성 원칙
- 결과 요약은 조건별 수치를 먼저 확인한 뒤 작성한다.
- 설명 우선순위:
  - 바닥 위치 영향 여부
  - 중첩 순서 영향 여부
  - 의류 자체 차폐 영향 여부
  - 다중 태그 간섭 영향 여부
  - 필요 시 최소 인식 횟수 기준 조정 필요 여부
- 훅 분석에서는 다음 우선순위도 함께 적용한다.
  - 정면/후면 차이
  - 방향 불일치 영향
  - 벽면/훅 구조 반사 및 산란 영향
  - 의류 차폐 영향

## AI 프롬프트용 사용 메모
- 결과를 AI 프롬프트에 넣을 때는 반드시 `위치`, `정면/후면`, `옷안/옷밖`, `QR 보이게/안보이게`, `절사평균`, `한 줄 요약`을 함께 제공한다.
- 후반 테스트를 해석할 때는 초반 `옷 1벌` 기준선과 비교하여 `원래 취약한 조건인지`, `후반에 새로 무너진 조건인지`를 구분하도록 프롬프트를 작성한다.
