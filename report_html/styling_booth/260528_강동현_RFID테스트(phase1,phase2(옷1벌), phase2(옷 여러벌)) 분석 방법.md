# 자료 분석 총정리

## 목적
이 문서는 RFID 실험 CSV를 어떻게 수집했고, 그 CSV를 어떤 기준으로 비교·해석했는지를 재현 가능하게 남기기 위한 문서다.

이 문서의 목표는 아래 3가지다.

1. 나중에 같은 CSV를 다시 분석할 때 동일한 기준으로 해석할 수 있게 한다.
2. 현재 분석 결론이 왜 그렇게 나왔는지, 어떤 기준선과 어떤 비교 절차를 거쳤는지 추적 가능하게 한다.
3. 분석 결과가 틀렸는지 검토하거나, 다른 사람이 같은 방식으로 재분석할 수 있도록 절차를 표준화한다.

## 데이터 수집 방식

### 기본 원리
CSV는 수동으로 표를 옮겨 적은 것이 아니라, 펌웨어가 시리얼로 출력한 로그를 PC에서 받아 자동 저장한 것이다.

분석에 사용한 흐름은 아래와 같다.

1. 펌웨어가 RFID 스캔 중 시리얼 로그를 출력한다.
2. PC에서 `capture_rfid_csv.py`를 실행해 시리얼 포트에 연결한다.
3. 스크립트는 모든 시리얼 로그를 `.txt` 원본 로그로 저장한다.
4. 이 중 `CSV,`로 시작하는 라인만 골라 구조화된 `.csv` 파일에 따로 저장한다.
5. 이후 분석은 이 CSV를 기준으로 진행한다.

즉, 사람이 시리얼 모니터를 보면서 필요한 숫자를 일일이 복사한 것이 아니라, 펌웨어가 이미 CSV 형식으로 내보낸 행만 자동으로 수집한 것이다.

### capture_rfid_csv.py가 실제로 하는 일
스크립트의 핵심 동작은 아래와 같다.

1. 시리얼 포트 연결
- `--port`를 지정하면 해당 포트를 사용한다.
- 지정하지 않으면 연결된 포트를 자동 탐지한다.
- baudrate 기본값은 `115200`이다.

2. 저장 파일 생성
- 실행 시각 기준으로 파일명을 만든다.
- 같은 시각에 아래 2개 파일이 함께 생성된다.
  - `serial_log_YYYYMMDD_HHMMSS.txt`
  - `rfid_capture_YYYYMMDD_HHMMSS.csv`

3. 실험 메타데이터 전송
- 스크립트는 시작 직후 펌웨어로 `META` 명령을 보낸다.
- 이 메타데이터에는 아래 정보가 포함된다.
  - `LABEL`: 실험 이름
  - `RUN`: 회차
  - `STEP`: phase 구분
  - `LOCATION`: 위치
  - `PATTERN`: 배치 패턴
  - `EXPECTED`: 기대 태그 수
  - `MEMO`: 메모
- 이 값들은 이후 펌웨어가 출력하는 CSV 행에 반영되도록 설계된 메타정보다.

4. 로그 저장 방식
- 시리얼에서 읽은 모든 줄은 먼저 raw log(txt)에 그대로 저장한다.
- 이 중 `CSV,`로 시작하는 라인만 CSV 파서로 분리해 표 형식으로 저장한다.
- 컬럼 개수가 미리 정의한 헤더 수와 다르면 malformed row로 보고 버린다.

5. 저장되는 CSV 컬럼
아래 헤더가 고정으로 저장된다.

- `record_time_ms`
- `experiment_label`
- `run_number`
- `test_step`
- `location`
- `pattern`
- `expected_tag_count`
- `session_id`
- `configured_scan_time_sec`
- `row_type`
- `actual_scan_time_ms`
- `first_read_time_all_ms`
- `first_valid_read_time_ms`
- `total_unique_tags`
- `valid_tag_count`
- `recognition_rate_pct`
- `ghost_read_count`
- `raw_tag_id`
- `server_tag_id`
- `tag_read_count`
- `tag_first_read_time_ms`
- `passed_minimum_rule`
- `server_send_state`
- `memo`

### 정리
즉, 분석에 쓴 CSV는 아래 두 단계를 거쳐 만들어진다.

- 펌웨어가 시리얼로 CSV 형식 로그를 출력
- PC 스크립트가 그 CSV 라인만 자동 저장

따라서 분석 출발점은 이미 구조화된 수집 로그이고, 이 문서의 핵심은 그 구조화된 CSV를 어떤 기준선과 비교했는지다.

## 공통 판정 기준

### 통과 기준
모든 분석에서 기본적으로 사용한 인식 통과 기준은 아래와 같다.

- `10초 이내 5번 이상 인식`

이 기준은 펌웨어 쪽 운영 기준과 맞춘 것이다.

### 실패 판단 기준
여러 벌 실험에서는 아래와 같이 판단했다.

- 목표 태그들 중 하나라도 기준을 못 넘으면 해당 조건은 `인식 X` 또는 `실패 조건`으로 본다.

### 반복 측정 통계 방식
기존 문서들에서 사용한 방식 그대로 통일했다.

1. 각 조건은 기본적으로 5회 반복 측정한다.
2. 최고값 1개와 최저값 1개를 제외한다.
3. 남은 3회의 평균을 대표값으로 사용한다.

이 절사평균은 아래 항목에 적용했다.

- 인식 횟수
- 최초 인식 시간
- 필요 시 다른 태그 누적 횟수

### 숫자 처리 원칙
- 원값을 임의로 보정하지 않는다.
- 미인식은 `0` 또는 `-`로 원문 기준에 맞춰 표시한다.
- 파일에 4회만 있는 경우는 해당 문서에서 따로 주석을 달고 해석했다.

## 기준선 문서의 역할

## 1. Phase 1 분석결과의 역할
Phase 1은 `하드웨어 기본 기준선`이다.

여기서 확인한 것은 아래와 같다.

- 위치 자체의 음영지역 여부
- 같은 태그라도 방향이 바뀌면 얼마나 민감한지
- 특정 위치에서 원래 인식이 강한지 약한지
- 최초 인식 속도가 위치별로 어떻게 다른지

즉, Phase 1은 "의류나 사람이나 다중 태그가 없을 때도 이 위치가 원래 약한가"를 보는 문서다.

### Phase 1에서 잡은 기본 분류
- 중앙 위치
- 왼쪽 위치
- 오른쪽 위치
- 아래쪽 위치
- 왼쪽아래
- 오른쪽아래
- 왼쪽 높은 곳
- 오른쪽 높은 곳
- 정방향 / 뒤집힘 / 세워짐

### Phase 1을 나중에 왜 다시 보는가
Phase 2에서 어떤 조건이 무너졌을 때, 그 이유가
- 원래 그 위치의 약점인지
- 의류가 추가되어 생긴 문제인지
- 다중 태그 간섭인지
를 구분하기 위해서다.

예를 들어,
- Phase 1에서 이미 약했던 위치라면 구조적 음영 가능성을 먼저 본다.
- Phase 1에서는 안정적이었는데 Phase 2에서만 무너지면 의류 차폐, 중첩, 사람, 안테나 위치 등의 추가 요인을 본다.

## 2. Phase 2(옷1벌) 분석결과의 역할
Phase 2(옷1벌)은 `실사용 단일 의류 기준선`이다.

Phase 1이 하드웨어 기준선이라면, Phase 2(옷1벌)은 실제 의류 1벌이 들어왔을 때의 운영 기준선이다.

여기서 확인한 것은 아래와 같다.

- 훅 위치별 약점과 강점
- 바닥 위치별 안정성
- 정면/후면 차이
- 옷 안/밖 배치 차이
- QR 보이게/안보이게 차이
- 1겹, 2겹, 5겹 차폐에 대한 반응

이 문서가 중요한 이유는, 이후 `옷 여러벌` 테스트를 분석할 때 단일 의류에서는 괜찮던 조건이 다중 의류에서 왜 무너졌는지 추적하는 출발점이 되기 때문이다.

## 3. Phase 2(옷여러벌) 분석결과의 역할
Phase 2(옷여러벌)은 `원인 분리와 개선 우선순위 도출` 문서다.

여기서는 아래 순서로 원인을 좁혀 갔다.

1. 재질 차폐 영향이 큰가
2. 훅 밀집과 벽 근접이 더 큰가
3. 바닥 적층 방향이 핵심인가
4. 사람 존재가 얼마나 악화시키는가
5. 안테나 위치를 바꾸면 회복 가능한가

즉, 단순히 "안 읽힌다"가 아니라, 어떤 구조에서 왜 안 읽히는지를 단계적으로 분해한 것이다.

## 위치와 방향 매칭 방식

## 기본 원칙
분석에서 가장 중요했던 것은 `실험 이름이나 파일명에 적힌 표현을 표준 위치와 방향으로 먼저 통일`하는 것이었다.

왜냐하면 서로 다른 실험 문서에서 같은 위치를 다르게 부르거나, QR이 보이느냐 안 보이느냐를 방향 표현 대신 썼기 때문이다.

## 위치 매칭
기존 문서 기준으로 아래처럼 맞춰서 해석했다.

| 원문 표현 | 표준 해석 |
| --- | --- |
| 왼쪽훅 | 좌측 상단 훅 |
| 중앙훅 | 정중앙 훅 |
| 오른쪽훅 | 우측 상단 훅 |
| 바닥 중앙 | 바닥 정중앙 |
| 바닥 왼쪽 | 바닥 좌측 구석 또는 좌측 바닥 |
| 바닥 오른쪽 | 바닥 우측 구석 또는 우측 바닥 |
| 왼쪽위, 왼쪽 높은 곳 | 좌측 상단 훅 계열 |
| 오른쪽위, 오른쪽 높은 곳 | 우측 상단 훅 계열 |

### Phase 1 참조 우선순위
Phase 2 조건을 Phase 1과 비교할 때는 가장 가까운 위치 기준선을 골랐다.

- 바닥 중앙 테스트 -> Phase 1 중앙 위치 우선 참조
- 바닥 왼쪽 테스트 -> Phase 1 왼쪽 위치, 필요 시 왼쪽아래 참조
- 바닥 오른쪽 테스트 -> Phase 1 오른쪽 위치, 필요 시 오른쪽아래 참조
- 훅 상단 테스트 -> Phase 1 왼쪽 높은 곳 / 오른쪽 높은 곳 참조
- 훅 측면 테스트 -> Phase 1 왼쪽 위치 / 오른쪽 위치 참조
- 뒤쪽/후방 조건 -> 실제 안테나 기준으로 가장 가까운 상부 또는 측면 위치 결과 참조

즉, 위치 매칭은 이름을 그대로 1:1 대응한 것이 아니라, 실제 물리 위치와 안테나 상대 위치가 가장 비슷한 기준선으로 묶었다.

## 방향 매칭
방향은 아래처럼 통일했다.

| 원문 표현 | 표준 해석 |
| --- | --- |
| QR 안보이게 | 정방향 |
| QR 보이게 | 역방향 |
| 뒤집음, 뒤집어 배치 | 역방향 |

이렇게 통일한 이유는 QR 노출 여부가 실제로는 `태그 면이 리더기를 보는지/등지는지`와 연결되어 있었기 때문이다.

### 훅 실험에서의 정면/후면 해석
- `정면`은 태그 면이 상대적으로 안테나 방향을 더 잘 보는 조건
- `후면`은 태그가 옷이나 벽/훅 구조 쪽을 향해 돌아간 조건

따라서 후면에서만 크게 무너지는 경우는 단순 차폐보다
- 방향 불일치
- 벽/훅 구조 반사
- 태그 면 각도 불리
를 함께 의심했다.

## 실제 분석 절차

## 1단계. CSV 수집
실험을 진행할 때마다 `capture_rfid_csv.py`로 해당 회차의 로그를 저장했다.

저장 시 같이 넣은 메타정보는 아래와 같다.

- 실험 라벨
- 회차
- step(phase 구분)
- location
- pattern
- expected tag count
- memo

이 메타정보 덕분에 같은 포맷의 CSV라도 나중에 위치별, 패턴별로 다시 묶어 해석할 수 있었다.

## 2단계. 대상 태그 고정
각 분석 단계마다 먼저 `이번 문서에서 주로 볼 태그`를 고정했다.

예시:
- Phase 2(옷1벌): 파란셔츠 `AA000010`
- 재질 차폐 테스트: 파란셔츠, 민감 태그, 최하단 태그 같이 비교
- 다중 옷 테스트: 태그별 유불리 비교
- 사람 유무 테스트: 파란셔츠, 강한 태그, 약한 태그 비교

즉, CSV에 있는 모든 태그를 동일 비중으로 보지 않고, 실험 목적에 맞는 주 태그와 비교 태그를 먼저 정했다.

## 3단계. 반복 측정 대표값 산출
각 조건은 5회 반복 측정값을 보고
- 최고 1개 제거
- 최저 1개 제거
- 나머지 3개 평균
으로 대표값을 만들었다.

이 절사평균을 쓴 이유는 특정 회차의 우발적 튐값 때문에 결론이 흔들리지 않게 하기 위해서다.

## 4단계. 통과/실패 판정
대표값과 회차별 값 둘 다 보면서 아래를 같이 판단했다.

- 10초 이내 5회 이상 읽혔는가
- 최초 인식 시간이 지나치게 늦지 않은가
- 반복해서 0회 또는 미인식이 발생하는가
- 특정 태그만 선택적으로 무너졌는가

즉, 단순 평균만 본 것이 아니라 `실제 운영에서 누락 위험이 있는지`를 같이 봤다.

## 5단계. 기준선과 비교
분석 목적에 따라 기준선을 다르게 잡았다.

### A. Phase 1과 비교할 때
이 비교는 `하드웨어 원래 취약 위치인지` 확인할 때 사용했다.

주로 아래를 봤다.
- 같은 위치 계열에서 원래 인식 횟수가 낮았는가
- 같은 위치 계열에서 최초 인식이 원래 느렸는가
- Phase 1에서는 안정적이었는데 지금만 무너졌는가

### B. Phase 2(옷1벌)과 비교할 때
이 비교는 `다중 의류나 사람 개입 때문에 추가로 무너졌는지` 확인할 때 사용했다.

주로 아래를 봤다.
- 단일 의류에서는 괜찮았는데 여러 벌에서만 무너졌는가
- 정면은 괜찮고 후면만 무너졌는가
- 같은 훅인데 밀집/분산에 따라 태그별 유불리가 뒤바뀌는가

## 6단계. 원인 분리 순서로 해석
최종 해석은 아래 순서로 좁혀 갔다.

1. 재질 차폐 때문인가
2. 훅 위치/벽 근접 때문인가
3. 태그끼리 밀집·중첩되어 결합/상쇄가 생겼는가
4. 사람 존재가 전파 경로를 막았는가
5. 안테나 위치를 바꾸면 회복되는가

이 순서를 쓴 이유는, 실제 결과상 `옷 재질 영향은 작고`, `배치/방향/안테나 위치 영향이 더 컸기 때문`이다.

## 단계별로 기준 실험을 어떻게 활용했는가

## A. Phase 1 활용 방식
Phase 1은 모든 후속 분석의 출발점이었다.

### 활용 목적
- 원래 이 위치가 약한가
- 원래 이 방향이 불리한가
- 구조적 음영인가

### 활용 예시
- 바닥 중앙이 후반에도 강하면 원래도 강한 위치였는지 확인
- 왼쪽훅 후면이 무너지면, 원래 왼쪽 상부 위치가 약했는지 확인
- 높은 위치 테스트가 약했다면 훅 상단 조건의 구조적 약점 가능성 검토

즉, Phase 1은 `원래 하드웨어 기본 성향`을 설명하는 기준선으로 썼다.

## B. Phase 2(옷1벌) 활용 방식
Phase 2(옷1벌)은 여러 벌 분석의 직접 비교 기준으로 썼다.

### 활용 목적
- 단일 의류에서는 가능한 조건이었는가
- 여러 벌이 되면서 무엇이 추가로 무너졌는가

### 활용 예시
- 왼쪽훅 정면은 옷 1벌에서 안정적이었다 -> 여러 벌에서 실패하면 밀집/벽 간섭/앞뒤 순서 영향 의심
- 바닥은 1겹, 2겹, 5겹에서도 안정적이었다 -> 여러 벌 바닥 실험이 무너지면 단순 차폐보다 적층 방향/태그 결합 의심
- 훅 후면이 옷1벌에서도 취약했다 -> 여러 벌에서 더 나쁘면 원래 취약 조건에 추가 간섭이 얹힌 것으로 해석

즉, Phase 2(옷1벌)은 `실사용 단일 기준선`이다.

## C. Phase 2(옷여러벌)에서 실제 사용한 비교 구조
옷 여러벌 문서에서는 아래처럼 비교했다.

### 1. 중앙훅 재질 차폐 테스트
- 기준군: 옷만 있는 중앙훅 조건
- 비교군: 바람막이만 추가, 청바지만 추가, 둘 다 추가
- 목적: 재질 차폐가 진짜 주원인인지 확인
- 결론: 전체가 같이 무너진 것이 아니라 특정 태그만 무너져 재질보다 위치/겹침/방향 영향이 더 큼

### 2. 훅 다중 옷 테스트
- 기준: 단일 의류 훅 테스트에서의 정면/후면 성향
- 비교: 한 훅 밀집 vs 여러 훅 분산
- 목적: 전체 약화인지, 태그별 선택적 매몰인지 확인
- 결론: 배치가 바뀌면 태그마다 유불리가 뒤집힘

### 3. 바닥 중첩 테스트
- 기준: 바닥 단일 의류 또는 바닥 안정 위치 기준선
- 비교: 적층 방향, 최하단 태그 방향, 전체 정방향/역방향
- 목적: 태그 방향 정렬이 특정 태그를 지배적으로 강하게 만드는지 확인
- 결론: 같은 방향 태그끼리 보강되며 특정 태그만 강해지는 구조가 생김

### 4. 사람 유무 테스트
- 기준: `3-1 사람 없음`
- 비교: 방향 변경, 사람 서있기, 옷 대보기, 바닥에 놓기
- 목적: 사람이 단순 차폐인지, 배치 재편도 같이 일어나는지 확인
- 결론: 사람 존재는 대체로 악화 요인이지만, 사람 개입과 함께 위치 재편이 동시에 작용함

### 5. 안테나 위치 테스트
- 기준: 기존 안테나 위치 = `중앙에서 약간 오른쪽`
- 비교군: 왼쪽, 중앙, 오른쪽
- 대상 케이스: 원래 0~4회 수준으로 실패하던 케이스만 재실험
- 목적: 원래 실패 조건이 안테나 위치만 바꿔도 회복되는지 확인
- 결론: 4개 실패 케이스 모두 최소 1개 위치에서는 회복되었고, 전체적으로는 오른쪽이 가장 자주 유리했음

## 파일명과 메타데이터를 실제로 어떻게 읽었는가

분석할 때는 제목과 파일명을 단순한 이름이 아니라 `실험 조건 설명문`처럼 읽었다.

예시:
- `파란셔츠`
- `후면`
- `왼쪽훅`
- `옷밖`
- `QR 안보이게`
- `안테나 오른쪽`

이런 단어들을 아래 항목으로 분해했다.

- 대상 의류/태그
- 위치
- 방향
- 차폐 상태
- 배치 패턴
- 안테나 위치

즉, CSV 숫자를 보기 전에 먼저 파일명으로 조건을 표준화했다.

## 같은 방식으로 다시 분석할 때의 체크리스트

## 1. 데이터 수집
- `capture_rfid_csv.py`로 raw log와 csv를 같이 저장한다.
- 실험 시작 전에 label, run, step, location, pattern, expected, memo를 정확히 넣는다.
- 회차별 파일이 섞이지 않게 관리한다.

## 2. 대상 태그 확정
- 이번 실험의 주 분석 태그가 무엇인지 먼저 정한다.
- 비교 태그가 필요하면 민감 태그, 강한 태그, 최하단 태그를 함께 정한다.

## 3. 조건 표준화
- 위치를 표준 명칭으로 통일한다.
- QR 보이게/안보이게를 정방향/역방향으로 환산한다.
- 정면/후면, 옷안/옷밖, 차폐 겹수, 안테나 위치를 따로 기록한다.

## 4. 통계 처리
- 5회 측정값 중 최고 1개, 최저 1개를 제거한다.
- 남은 3회 평균을 대표값으로 쓴다.
- 최초 인식 시간과 인식 횟수를 같이 본다.

## 5. 판정
- 10초 이내 5회 이상이면 통과로 본다.
- 특정 태그만 실패하는지, 전체가 같이 실패하는지 구분한다.
- 최초 인식 시간이 지나치게 늦으면 운영 리스크로 표시한다.

## 6. 기준선 선택
- 하드웨어 기본 성향을 보고 싶으면 Phase 1과 비교한다.
- 단일 의류에서는 가능했는지 보고 싶으면 Phase 2(옷1벌)과 비교한다.
- 여러 벌 실험에서는 옷1벌 기준선에서 무엇이 추가됐는지 설명한다.

## 7. 최종 해석 순서
항상 아래 순서로 원인을 좁힌다.

1. 재질 차폐
2. 위치/벽 근접
3. 방향 불일치
4. 태그 밀집/중첩
5. 사람 개입
6. 안테나 위치

## 최종 정리
이 프로젝트에서 분석은 단순히 CSV 숫자를 읽는 작업이 아니라, `기준선 대비 어떤 조건이 추가되었는지`를 단계적으로 제거하며 원인을 좁히는 방식으로 진행했다.

핵심은 아래 2가지다.

1. Phase 1은 하드웨어 기본 기준선, Phase 2(옷1벌)은 실사용 단일 기준선으로 활용했다.
2. Phase 2(옷여러벌)은 이 두 기준선을 바탕으로 재질, 밀집, 방향, 사람, 안테나 위치를 차례로 분리해서 원인을 추적했다.

따라서 앞으로 같은 CSV를 다시 분석할 때도, 반드시
- 위치/방향을 먼저 표준화하고
- 어떤 기준선과 비교할지 정한 뒤
- 절사평균과 통과 기준을 동일하게 적용하고
- 재질보다 배치/방향/중첩/안테나 위치를 우선 검토하는 순서
를 유지해야 동일한 결론에 도달할 수 있다.
